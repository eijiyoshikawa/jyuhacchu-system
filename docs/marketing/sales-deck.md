## 2. ターゲットと解決する課題

### 2-1. ターゲット顧客像
- 年商 数億〜数十億円規模の中小企業
- 発注書・請求書を月数十〜数千件扱う事業者
- インボイス制度・電子帳簿保存法への対応を進めたい経理・総務部門
- 紙や Excel、メールで受発注業務を回していて、承認ワークフローを整備したい管理部門

### 2-2. 解決する課題

| 現状の課題 | 本サービスによる解決 |
|----------|------------------|
| 発注書をExcel・Wordで個別作成しフォーマットが統一されていない | テンプレート化された発注書で全社共通フォーマットを強制 |
| 承認の押印フローで業務が止まる | 電子承認ワークフローで承認スピードを大幅短縮 |
| 取引先が適格請求書発行事業者かどうか都度確認 | 国税庁Web-API連携で登録番号を自動検証 |
| 免税事業者対応の税額計算が煩雑 | 経過措置の控除率（80%→50%→0%）を自動適用 |
| 電子帳簿保存法 電子取引要件の未対応 | 確定時ハッシュ＋タイムスタンプ、検索3項目を標準搭載 |
| 監査・内部統制の証跡が残らない | 全操作を監査ログに自動記録、ADMINから閲覧可能 |

## 3. 機能一覧（補助金審査向け詳細）

### 3-1. 発注管理機能（補助対象類型の中核）

| 機能 | 詳細 |
|------|------|
| 発注書作成 | 明細行追加、品名・仕様・数量・単位・単価・金額を入力。税抜→税込の自動計算。 |
| 発注番号 自動採番 | `PO-YYYYMMDD-XXXX` 形式で連番採番し重複を防止 |
| 承認ワークフロー | 多段階承認（申請→1次承認→2次承認→…→発注済）。却下時はコメント必須、差戻し可能 |
| ステータス遷移 | 下書き→申請中→承認済→発注済→請負済→納品完了→検収完了（8状態） |
| 確定（電帳法対応） | 検収完了時点で SHA-256 ハッシュと確定日時を記録。以後は編集不可 |
| 発注書印刷 | A4最適化のPDF／印刷ページ。適格請求書対応の登録番号表記、取引契約必要記載事項欄を完備 |
| 取引契約 必要記載事項チェック | 案件名称・納入先・履行期間・取引金額・支払条件・契約日の欠落を自動検出し準拠バッジ表示 |

### 3-2. 取引先管理機能

| 機能 | 詳細 |
|------|------|
| 取引先マスタ CRUD | 会社コード、会社種別（発注企業／受注企業）、住所、電話、メール、インボイス番号 |
| インボイス番号 検証 | フォーマット検証（T + 13桁数字）＋ 国税庁Web-APIによる有効性・登録事業者名照合 |
| 免税事業者判定 | 登録番号未設定＝免税事業者として扱い、発注書作成時に画面上で警告表示 |

### 3-3. 請求管理機能

| 機能 | 詳細 |
|------|------|
| 請求書作成 | 発注書から請求書を自動生成（明細を引き継ぎ） |
| 請求番号 自動採番 | `INV-YYYYMMDD-XXXX` 形式 |
| 適格請求書出力 | 登録番号・税率別合計・消費税額を明記した A4 印刷レイアウト |
| CSV出力 | BOM付きUTF-8でExcel直読み込み可能 |
| ステータス管理 | 下書き→提出済→承認済→支払済（4状態） |
| 確定（電帳法対応） | 発注書と同様にハッシュ＋タイムスタンプ記録 |

### 3-4. インボイス制度対応（補助金必須要件）

| 項目 | 対応内容 |
|------|---------|
| 適格請求書発行事業者登録番号 | 取引先／自社マスタに登録、国税庁API自動検証 |
| 標準税率10% / 軽減税率8% 混在 | 明細ごとに税率設定、税率別合計を表示・出力 |
| 免税事業者の経過措置 | 2023/10〜:控除80%、2026/10〜:控除50%、2029/10〜:控除0%を日付基準で自動適用 |
| 控除可能／不可税額の可視化 | 発注書作成画面の TaxSummary コンポーネントで視覚的に表示 |
| 適格請求書フォーマット | 請求書印刷レイアウトで要件（登録番号・税率別対価・税額・発行者名等）を充足 |

### 3-5. 電子帳簿保存法対応

| 項目 | 対応内容 |
|------|---------|
| 電子取引要件（2024年1月義務化） | 発注書・請求書データをクラウドに原本保存 |
| 改ざん防止措置 | SHA-256 ハッシュ＋確定タイムスタンプを自動付与 |
| 検索要件3項目 | 取引年月日・取引金額・取引先名による絞り込みを標準画面で提供 |
| スキャナ保存要件 | 解像度・タイムスタンプ要件を満たす文書保管（今後のアップデートで拡張予定） |

### 3-6. 承認ワークフロー／権限管理

| 機能 | 詳細 |
|------|------|
| 多段階承認 | ApprovalFlow テーブルで柔軟な承認経路を設定 |
| 承認コメント | 却下理由を記録し再申請時の修正材料に |
| ロールベース権限 | 管理者 / 発注担当 / 受注担当 の3ロール |
| マルチテナント分離 | 会社ID（companyId）による自動スコープ、ADMIN のみ横断参照可 |
| 監査ログ | 全作成・更新・削除・承認をAuditLogに記録、IPアドレス・操作内容を保持 |

### 3-7. ダッシュボード・レポート

- 発注件数／請求件数／承認待ち件数／今月の発注金額 サマリーカード
- 最近の発注・請求 TOP5 リスト
- ページネーション・検索・ステータスフィルター標準装備

## 4. 補助金要件適合の明示

デジタル化・AI導入補助金2026 インボイス枠 インボイス対応類型の機能要件に対する本サービスの適合状況。

| 要件 | 本サービスの充足状況 |
|------|----------------|
| 会計／受発注／決済のうち1機能以上 | **受発注機能**を中核機能として保有（発注書作成・承認・請求・取引先管理を提供） |
| インボイス制度対応 | 適格請求書発行事業者番号の入力・国税庁API検証、税率別合計表示、適格請求書出力に対応 |
| クラウド型ソフトウェア | SaaS形態、Webブラウザのみで利用可能 |
| 交付申請者に対するアカウント発行 | 管理者画面からユーザー登録、ロール付与可能 |
| 導入後の継続利用に必要な保守・サポート | 月額契約＋メール／チャットサポートで提供 |

### 申請にあたっての前提要件（利用者側）

- GビズIDプライムの取得が必須
- SECURITY ACTION 宣言（★一つ星以上）が必須
- みらデジ経営チェックの実施が求められる場合あり

※最新の公募要領（中小機構 デジタル化・AI導入補助金ポータルサイト）で必ずご確認ください。
